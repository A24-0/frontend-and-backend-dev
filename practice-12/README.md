## 1. Итоги: полная система авторизации (практики 7–11)

### Общая схема

| Этап | Практика | Что реализовано |
|------|----------|-----------------|
| **7** | Базовые методы аутентификации | Регистрация, вход, хеширование паролей (bcrypt + соль), CRUD товаров, защита маршрутов по id |
| **8** | JWT | Выдача access-токена при входе, защищённый маршрут `GET /api/auth/me`, проверка токена в middleware |
| **9** | Cookie и кэширование | Безопасные cookie (HttpOnly, Secure, SameSite), кэш выданных токенов, отзыв при logout |
| **10** | Refresh-токены | Refresh-токен (7d), `POST /api/auth/refresh`, отслеживание сессий, `GET /api/auth/sessions` |
| **11** | RBAC и blacklist | Роли (admin, user, moderator), проверка ролей на маршрутах, blacklist при утечке токена |

### Поток аутентификации (кратко)

1. **Регистрация** — пароль хешируется (bcrypt), в БД/памяти хранится только хеш.
2. **Вход** — проверка пароля через `bcrypt.compare`, выдача access- и refresh-JWT; при необходимости — установка cookie.
3. **Запросы** — клиент передаёт access-токен (заголовок `Authorization: Bearer <token>` или cookie); сервер проверяет подпись, срок, кэш/blacklist и при необходимости роль.
4. **Обновление** — по refresh-токену выдаётся новый access без повторного ввода пароля.
5. **Выход** — токен отзывается (удаление из кэша и/или добавление в blacklist), cookie очищаются.

### Где что лежит в проекте

- **practice-7-8** — регистрация, логин, JWT, защищённые маршруты товаров.
- **practice-9** — cookie (HttpOnly, SameSite, Secure), кэш токенов.
- **practice-10** — refresh-токены, сессии.
- **practice-11** — роли (RBAC), blacklist, админ-маршруты.

## 2. Сводка маршрутов по практикам

| Маршрут | Практика | Назначение |
|---------|----------|------------|
| POST /api/auth/register | 7 | Регистрация (пароль в хеше) |
| POST /api/auth/login | 7–8 | Вход, выдача access (и при 9–11 — refresh, cookie) |
| GET /api/auth/me | 8 | Текущий пользователь (по токену) |
| POST /api/auth/logout | 9–11 | Выход (кэш/blacklist, очистка cookie) |
| POST /api/auth/refresh | 10–11 | Новый access по refresh |
| GET /api/auth/sessions | 10–11 | Список сессий пользователя |
| GET /api/users | 11 | Список пользователей (admin) |
| PATCH /api/users/:id/role | 11 | Смена роли (admin) |
| POST /api/admin/blacklist | 11 | Блокировка токена при утечке (admin) |
| GET/POST /api/products, GET/PUT/DELETE /api/products/:id | 7–11 | CRUD товаров (часть маршрутов по ролям в 11) |
